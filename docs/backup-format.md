# Y-TEC Wi-Fi Capsule バックアップ形式 v1

## ファイル

- 拡張子: `.ywcwifi`
- マジック: ASCII `YTECWCAP`
- 形式版: 1
- アプリ鍵ID: 1

Y-TEC Data Capsuleの`.ywbwifi`とはマジック、鍵素材、鍵導出ラベルが異なり、相互復号しない。

アプリ鍵ID `1` はWi-Fi Capsule形式の鍵スロットを表す。公式、カスタム、公開開発の各ビルドは同じ鍵IDを使用するが、鍵値が異なるため相互復号できない。Y-TEC公式版は1.0.0以降で同じ互換鍵を使用する。

## 暗号方式

- マスター鍵: 公式／カスタムビルドではビルド時に埋め込む32バイト鍵。公開開発ビルドでは公開ラベルからSHA-256で導出する32バイト鍵
- ソルト: バックアップごとにCSPRNGで生成する16バイト
- IV: バックアップごとにCSPRNGで生成する16バイト
- 暗号: AES-256-CBC / PKCS#7
- 改ざん検知: HMAC-SHA-256
- 構成: Encrypt-then-MAC

暗号鍵と認証鍵は、マスター鍵をHMAC鍵として、製品固有ラベル、用途バイト、ソルトから個別に導出する。HMACが一致するまで復号処理へ進まない。

## 平文ヘッダー

整数はlittle-endian。固定長46バイト。

| Offset | Size | 内容 |
| ---: | ---: | --- |
| 0 | 8 | `YTECWCAP` |
| 8 | 1 | 形式版 `1` |
| 9 | 1 | アプリ鍵ID `1` |
| 10 | 16 | ランダムソルト |
| 26 | 16 | ランダムIV |
| 42 | 4 | 暗号文長 |

ヘッダーと暗号文を連結した全体へHMAC-SHA-256を計算し、末尾32バイトへ保存する。未知の版／鍵ID、長さ不一致、切断、末尾追加、ヘッダー／暗号文／タグ改ざんを拒否する。

平文ヘッダーにSSID、Wi-Fiキー、XML、プロファイル数、作成PC、ユーザー名、パスを含めない。

## 暗号化ペイロード

UTF-8 JSON。

```json
{
  "schemaVersion": 1,
  "productId": "ytec-wifi-capsule",
  "createdAt": "2026-07-28T12:00:00+09:00",
  "profiles": [
    {
      "name": "暗号化領域内のプロファイル名",
      "xml": "Base64化されたWLANProfile XML"
    }
  ]
}
```

復号後に各XMLを再解析し、JSON上の名前とXMLルート直下の名前が完全一致することを確認する。大文字小文字だけ異なる重複名も拒否する。

## 上限

- プロファイル数: 1～256
- 1プロファイルXML: 最大1 MiB
- XML合計: 最大16 MiB
- ペイロード: 最大24 MiB
- 完成ファイル: 約24 MiB + ヘッダー／パディング／タグ

未知の内容スキーマを推測で開かない。

## 互換性

ポインター長、ネイティブ構造体、CPU固有バイト列を保存しない。32ビット／64ビットの両方向で同じ形式を読み書きする。
