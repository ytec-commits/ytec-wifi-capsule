# 脅威モデル

更新日: 2026-08-25

## 保護するもの

- Wi-Fi共有キー／パスフレーズ
- Wi-FiプロファイルXML
- 暗号化領域内のプロファイル名
- 既存Windows Wi-Fi設定

## 想定する脅威

- USBメモリー、外付けドライブ、バックアップファイルの紛失
- バックアップの偶発的な破損
- 攻撃者によるヘッダー、暗号文、タグの改ざん
- 別製品形式、未知の版、切断、末尾追加の入力
- 悪意あるXMLのDTD／外部実体
- 復元時の意図しない同名設定上書き

## 対策

- AES-256-CBCとHMAC-SHA-256のEncrypt-then-MAC
- バックアップごとのランダムソルトとIV
- 用途別に暗号鍵と認証鍵を導出
- 固定時間比較後だけ復号
- 版、鍵ID、長さ、内容スキーマ、XMLを段階検証
- DTD禁止、外部リゾルバー無効、XMLサイズ上限
- `WlanGetProfile`／`WlanSetProfile`によるメモリ内処理
- 平文XML一時ファイルなし
- 完成ファイル上書きなし
- partial完全検証後だけ完成名へ移動
- 復元選択と上書き許可を別操作にする
- 外部通信、テレメトリー、クラウド同期なし

## アプリ内蔵鍵の境界

パスワード入力や鍵ファイルを使わず、32/64ビットやPCをまたいでY-TEC公式版から復元できることを優先する。公式マスター鍵は公開ソースへ保存せず、公式ビルド時にDLLリソースへ埋め込む。1.0.0以降の公式バックアップ互換性を維持する。

公開ソースの標準ビルドは、値が公開されている開発鍵を使う。このビルドは暗号処理とUIの開発・合成テスト専用であり、実データの秘匿性を提供しない。カスタム鍵ビルドは利用者が用意した32バイト鍵を埋め込むが、公式版や異なるカスタム鍵とは互換性がない。

保護できる主な状況は「バックアップ媒体だけを拾った人が、標準ツールやテキストエディターで容易にキーを読むこと」である。

次は保証しない。

- 実行ファイルの静的／動的解析への耐性
- プロセスメモリを読める攻撃者への耐性
- 公式実行ファイルまたはビルド環境から鍵を取得できる相手への耐性
- 利用者ごとの秘密分離
- 個別バックアップの鍵失効
- 製品内蔵鍵のオンラインローテーション

暗号アルゴリズムや形式を秘密にすることを安全性の前提にしない。内蔵鍵方式の制限をUI、README、操作マニュアルへ表示する。

## メモリ

Native Wi-Fi APIはXMLをUnicode文字列として返す。.NET上では一部の文字列が不変オブジェクトとしてGC回収まで残る可能性がある。管理対象のバイト配列、導出鍵、暗号文コピーは処理後にゼロ化するが、プロセスメモリからの完全消去は保証しない。

## ログ

永続ログを作らない。SSIDは利用者が項目を選ぶため画面へ表示する。Wi-Fiキー、XML、PC名、Windowsユーザー名、完全パスを画面の進捗やエラーへ出さない。

## 復元制限

- 移行先OSまたは無線LANアダプターが認証／暗号方式を理解できない場合
- グループポリシー管理プロファイル
- 企業802.1X証明書、外部証明書、スマートカード、ハードウェア鍵
- Windows側のDACLが読取／登録を許可しない場合

上記はプロファイル単位で失敗し得る。失敗時に既存設定を削除しない。
