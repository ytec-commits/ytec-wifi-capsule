# アーキテクチャ

## 目的

保存済みWi-Fiプロファイルを、利用者が一覧から選び、平文ファイルを残さず暗号化バックアップ／復元する。Windows 7 SP1～11、32/64ビット間で同じバックアップ形式を使う。

## 構成

```text
Ytec.WifiCapsule.App
  - WPF画面
  - 選択、確認、進捗、結果表示
  - 管理者マニフェストと1インスタンス制御

Ytec.WifiCapsule.Windows
  - WlanOpenHandle / WlanEnumInterfaces
  - WlanGetProfileList / WlanGetProfile
  - WlanSetProfile
  - 公式／カスタム／公開開発アプリ鍵の読込

Ytec.WifiCapsule.Core
  - WLANProfile XMLの安全な検証
  - 選択バックアップ／選択復元
  - .ywcwifi暗号コンテナ
  - 出力パスと完成トランザクション
```

UIはWindows APIを直接呼ばない。Coreは`IWifiProfileStore`へ依存し、本番はNative Wi-Fi実装、テスト／画面確認は合成実装を注入する。

## アプリ鍵ビルド

- Y-TEC公式版: リポジトリ外の32バイト互換鍵をビルド時にDLLリソースへ埋め込む。
- カスタム鍵版: 利用者が用意した32バイト鍵を埋め込む。公式版とは互換性がない。
- 公開開発版: 公開済みラベルから導出する開発鍵を使う。実データ用途ではない。

公式鍵ファイルはGit、ソースアーカイブ、ログ、Workflow Artifact、配布ZIPへ単独ファイルとして保存しない。実行ファイルには復号に必要な鍵が含まれるため、実行ファイル解析への耐性は保証しない。

## バックアップ

1. 選択アダプターのプロファイル一覧を再取得する。
2. 選択名が現在も存在することを確認する。
3. `WlanGetProfile`を`WLAN_PROFILE_GET_PLAINTEXT_KEY`付きで呼ぶ。
4. XMLサイズ、ルート、名前空間、プロファイル名、キー保護状態を検証する。
5. 選択項目だけをWi-Fi Capsule専用コンテナへ暗号化する。
6. 保存先と同じフォルダーの一意な`.partial-<GUID>`へ`CreateNew`で書く。
7. partialを先頭から復号し、件数と名前を再検証する。
8. 完成名へ上書きなしで移動する。

XMLはメモリ上だけで処理する。異常終了時も平文XML一時ファイルは存在しない。暗号化済みpartialは失敗時に限定名で削除する。

## 復元

1. 入力ファイルのサイズ、再解析ポイント、ローカルパスを検証する。
2. HMAC、暗号ヘッダー、内容JSON、全XMLを検証する。
3. 復元可能なプロファイル名だけを画面へ表示する。
4. 選択項目を復元先アダプターの現在一覧と比較する。
5. 上書き未許可の同名項目は変更せずスキップする。
6. 選択項目だけを`WlanSetProfile`へ渡す。

`WlanSetProfile`へ平文キーを含むXMLを渡した場合、Windowsはプロファイルストアへ保存する前にキーを暗号化する。

## 非対象

- Wi-Fi接続操作
- 利用可能ネットワークのスキャン
- 位置情報、BSSIDの取得
- Wi-Fiキーの画面表示
- XML／キーのエクスポート
- クラウド、外部API、テレメトリー
- 自動更新、ファイル関連付け
